Reverse a Transaction
in Applied Epic

Correct an incorrect billing entry by reversing the transaction directly from the policy record. This guide walks through selecting the policy, locating the transaction, and processing a full reversal — keeping your account billing records accurate.

3 Phases
13 Steps
~5 Minutes

Account Billing

What This Guide Covers

Use this workflow whenever a transaction has been entered incorrectly against a policy and needs to be fully reversed. The reversal is initiated from the policy's Transactions section via the Actions → Reverse Transaction menu. All line items on the original invoice must be selected before completing the reversal. This example uses a General Liability policy — the process is identical for any other policy type.

Locate the Policy ↓ Find the Transaction ↓ Process the Reversal ↓
Phase 01 Locate the Policy
1
Start at the policy list in Epic
Open Applied Epic and navigate to the policy list for the account. All transaction reversals begin at the policy level — you must be on the correct account's policy list before proceeding.
2
Select the policy the transaction was made on
Click the policy record that contains the incorrect transaction. In this example, that is the General Liability policy. The process is the same for any line of business.
Tip: If you're unsure which policy holds the transaction, check the account's billing summary first to confirm the policy line before opening it.
3
Click "Access"
With the policy selected, click the Access button to open the policy record. This loads the full policy detail view where billing and transaction data are available.
Phase 02 Find the Transaction
4
Click "Transactions"
Inside the policy record, click the Transactions tab or menu option. This opens the Transactions section scoped to the selected policy.
5
Review the transaction list
A list of all transactions made against this policy will populate in the Transactions section. These results are automatically filtered to only the transactions on the selected policy — no additional filtering is needed.
Note: Identify the incorrect transaction before proceeding. Confirm the amount, date, and type match the entry you intend to reverse.
6
Select the transaction to reverse
Click on the specific transaction record you need to reverse to highlight/select it. Only one transaction can be reversed at a time through this workflow.
Phase 03 Process the Reversal
7
Click "Actions"
With the transaction selected, click the Actions button in the Transactions toolbar. This opens a dropdown menu with available transaction operations.
8
Click "Reverse Transaction"
From the Actions dropdown, select Reverse Transaction. This opens the Reverse Transaction dialog, which lists all line items included in the original invoice.
Important: Reverse Transaction is a permanent accounting action. Verify you have selected the correct transaction before proceeding — reversals cannot be undone without creating a new transaction.
9
Click "Select All" to include all invoice line items
In the Reverse Transaction dialog, click Select All to ensure every line item on the invoice is included in the reversal. Partial reversals can create billing discrepancies.
Required: All items included in the original invoice must be selected. Do not reverse individual line items unless specifically instructed — always use Select All for a full reversal.
10
Verify that all items are selected
Confirm that every line item in the dialog now shows a checkmark or selected state before proceeding. The total reversal amount shown should match the full original transaction amount.
11
Select a Reason using the dropdown — choose "Incorrect Billing"
Open the Reason dropdown and select Incorrect Billing as the reversal reason. This reason is required for audit trail purposes and must be selected before the Finish button becomes available.
Note: Other reason codes may be available in the dropdown (e.g., Duplicate Entry, Carrier Return). Select the code that most accurately reflects why the transaction is being reversed.
12
Click "Finish"
Click the Finish button to complete the reversal. Epic will process the reversal and remove the original transaction entries from the policy's transaction list.
13
Confirm the reversal — verify the transaction list and account balance
After completing the reversal, confirm that the original transactions have been removed from the policy's transaction list. Then verify that the Account Balance has been updated to reflect the reversal. The workflow is complete once both are confirmed.
Next step: If the original transaction needs to be re-entered with corrected amounts, create a new invoice after confirming the reversal is reflected in the account balance.
Common Questions
What happens to the original transaction after a reversal? ▾

The original transaction entries are removed from the policy's transaction list and the account balance is updated to reflect the reversal. Epic creates offsetting entries behind the scenes to maintain a clean accounting record. The reversal itself may appear briefly in the transaction history depending on your Epic configuration, but the net effect on the account balance is zero — as if the original transaction never occurred.

Why is "Select All" required instead of picking individual line items? ▾

An invoice in Epic is treated as a single billing unit — premium, fees, taxes, and other charges are all tied together. Reversing only some line items while leaving others creates a partial reversal that can produce billing discrepancies between the agency and carrier records, cause commission tracking errors, and make it difficult to reconcile the account later. Always select all items unless you have been specifically instructed otherwise by your accounting manager.

Can a reversal be undone after clicking Finish? ▾

No — once a reversal is finalized, it cannot be undone through a simple cancel or undo action. If a reversal was processed in error, you will need to re-enter the original transaction manually as a new invoice to restore the correct billing record. This is why it's critical to confirm the correct transaction and verify all line items are selected before clicking Finish.

What reason code should I use if the transaction wasn't an incorrect billing? ▾

Use the reason code that most accurately reflects why the reversal is being made. Common options include Incorrect Billing (wrong amount or policy), Duplicate Entry (the transaction was posted twice), and Carrier Return (the carrier has returned premium). If you are unsure which code applies, consult your accounting manager before processing the reversal — the reason code is recorded in the audit trail and affects how the reversal is categorized in reporting.
