The Golden Rule

Before attaching any document or email, always check whether an activity already exists for what that document relates to. If one exists — attach to it. Epic will not create a new activity, and the document lands exactly where it belongs. Only drag to the policy line and select a code below when no existing activity applies.

Phase 01 The Add Attachment Process
1
Identify the document or email
Before touching anything in Epic, determine what you have. Is it a policy document, an endorsement, a cancellation notice, a client email requesting a certificate? The document type determines everything that follows.
2
Check for an existing activity
Navigate to the client's account and look for an open activity that already covers what this document relates to.
If a matching activity exists: attach directly to it. Do not proceed to step 3 — you are done. Epic will add the document to that activity and no new activity will be created.
If no matching activity exists: continue to step 3.
3
Drag the document to the policy line
Drag the document or email to the correct policy line in the client's account — not to the account level. Attaching to the policy line ensures the activity is created in the right context and the correct merge fields will populate.
4
Select the appropriate activity code
Epic will prompt you to create a new activity. Choose the code that matches the document type from the Add Attachment list. Use the reference guide below to identify the correct code. There are 3 categories for Nadler Insurance:
  • # codes — Document-driven. Start with the physical document. Used for insurance contract documents like policies, endorsements, cancellations.
  • $ code — Billing-driven. For billing and invoice questions outside the renewal cycle.
  • Alpha codes — Service-driven. Typically start with a client phone call or email — log the interaction, then attach supporting documents.
5
Assign to the responsible party
Before saving, assign the new activity to the correct responsible party at your agency. This ensures the right person is notified and the activity routes into the appropriate workflow queue.

Common Questions
What happens if I attach a document to the account instead of a policy line? ▼

Epic will still force a new activity to be created, but the activity won't be tied to a specific policy. Merge fields like &Policy#&, &LineCode&, and &PPECode& will not populate correctly, leaving you with a blank or incomplete activity name. Always drag to the policy line.

What is the difference between a # code and its ^ eDoc download equivalent? ▼

The # codes are used when you are manually attaching a document — you physically drag it to the policy line and select the code. The ^ equivalent is used when a document arrives via eDoc download through the Interface module. The activity coding format is identical; only the code prefix changes. For example, a manually attached policy uses #POL while a downloaded policy document uses ^POL.

When should I use an alpha service code vs a # document code? ▼

Think about what initiated the activity. If you have a physical document in hand — a policy, an endorsement, a cancellation notice — start with that document and use the corresponding # code. If the activity started because a client called or emailed you — a certificate request, a claim notice, a change request — log that interaction first using the appropriate alpha code, then attach any documents you receive to that activity.

Why does Epic force a new activity when I attach to a policy, account, or document? ▼

This is by design. Epic treats any attachment to a non-activity object as a new, standalone event that needs its own activity record for tracking and workflow purposes. The only way to avoid creating a new activity is to attach directly to an existing activity — Epic will then add the document to that activity's attachment list without generating a new one.
