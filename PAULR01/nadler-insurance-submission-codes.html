How Submission Codes Work

Unlike Add Attachment codes — which you select manually — Submission event codes are generated automatically based on how a submission is sent to the carrier. The method you use to submit determines the code that gets created. You don't choose the code; you choose the action, and Epic assigns the code.

Phase 01 The Submission Process
1
Identify the submission method
Before submitting, determine how you will send the application to the carrier. Are you using Epic's Submit Application action, dragging a document in, sending via email, using Tarmika, or submitting through Master Marketing? Each method creates a different activity code.
2
Execute the submission action in Epic
Use the appropriate action for your method. Manual actions are performed directly in Epic; system-triggered codes are created automatically by integrations such as Indio or Tarmika.
  • Submit Application — Active policy screen → Actions → Submit Application
  • Add Attachment — Drag & drop document into Epic
  • Update Stage — Master Marketing → Actions → Update Stage to Submitted
  • Submit to Carriers — Master Marketing → Actions → Submit to Carriers
  • Email — Send via Email within Epic
  • Tarmika Quote — Actions → Start Tarmika Quote
  • Tarmika Remarket — Actions → Start Tarmika Remarket Quote
  • Indio — System write-back when Indio delivers submission to carrier
3
Epic creates the activity automatically
Epic generates the submission activity using the code that corresponds to your method. The coding format is applied automatically — no manual entry required.
Standard coding format: Submitted to &PPEName& for quote on &PolDesc& — Epic populates the carrier name and policy description from the record automatically.
Tarmika Remarket exception: Uses a slightly different format — Submitted to Tarmika for REQUOTE on &PolDesc& — to distinguish remarketing from a fresh quote.
4
Verify the activity was created correctly
After submitting, confirm the activity appears on the account with the correct code and coding format. Use the reference guide below to verify the code matches the method you used. If the wrong code was generated, check that the correct action was taken in Epic.

Common Questions
Why are there multiple submission codes — can't I just use one?▼

Each code tracks a distinct submission pathway, which matters for reporting and workflow. Using SCAM (drag-and-drop) vs SCAP (Submit Application action) tells you later whether the submission went through Epic's formal process or was handled manually. The codes also trigger different downstream behaviors in some configurations, so using the right method — not just any method — is important.

What is the difference between SCAM and SCAP?▼

SCAP is generated when you use the formal Submit Application action from the active policy screen — this is the preferred method for new submissions as it routes through Epic's structured process. SCAM is generated when you drag and drop a document into Epic as an attachment, which is a more manual approach. Both log the submission, but SCAP is the cleaner workflow for standard carrier submissions.

What is the difference between SCAT and SCAR?▼

SCAT is created when you start a brand new Tarmika quote — first time submitting this risk to Tarmika. SCAR is created when you start a Tarmika remarket quote — you are going back to Tarmika for a requote on a risk you have previously submitted. The coding format reflects this: SCAR uses "REQUOTE" in the activity name so it is clearly distinguishable from a fresh submission in the activity history.

What generates SCAI — do I need to do anything?▼

SCAI is a system-generated code created automatically when Indio delivers a submission to a carrier. You do not need to take any action to create this activity — it is a write-back from the Indio integration. If you expect to see an SCAI activity and it is not there, check whether the Indio submission was successfully delivered to the carrier on the Indio side.
