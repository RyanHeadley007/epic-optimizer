Epic Processing Guide
Assigning Download Files
From Suspense

How to locate and assign a download file sitting in Interface Suspense to the correct existing policy — including filtering, sorting, and confirming the policy update.

9 Steps
~1 Minute
Applied Epic
Scenario
A download file has landed in Interface Suspense and needs to be manually assigned to the correct policy on the account. This workflow covers how to search for the matching policy — including enabling the Prospective and History filters to surface all available policies — sort by expiration date to find the right term, and select the existing policy to complete the assignment.
Interactive Walkthrough
Live Step-by-Step Guide — Epic Optimizer · 9 Steps
Processing Steps
Phase 1 — Account Search and Filtering
01
Select the Policy Transaction from Suspense
▼

Starting in the suspense area of Epic, select the policy transaction from the list that needs to be assigned.

ℹ This opens the assignment search screen where you will locate the matching policy on the account.
02
Enable "Prospective" and "History" Checkboxes
▼

Select both the Prospective and History checkboxes under the Existing Clients/Policies section to expand the search results beyond only active policies.

⚠ Without these checked, prior-term or future-dated policies may not appear in the results — causing you to miss the correct policy.
03
Click "Find"
▼

Click Find to refresh and reload the policy search results with the updated filter selections applied.

Phase 2 — Policy Selection and Assignment
04
Click the "Expiration" Column Header to Sort
▼

Click the Expiration column header to sort the policy list by expiration date, making it easier to identify the correct policy term.

05
Find the Policy with the Matching Effective Date Range
▼

Review the sorted list and locate the policy whose effective and expiration dates match the date range of the downloaded file.

⚠ Make sure the policy term dates align exactly with the transaction — do not select a policy with different dates or you may assign the file to the wrong term.
06
Click "Select Existing"
▼

With the correct policy highlighted, click Select Existing to attach the downloaded transaction to the existing policy on the account rather than creating a new policy record.

ℹ Selecting Existing keeps the account clean and avoids duplicate policy records.
07
Click "Update Existing"
▼

In the Suspense Policy Line Detail window that opens, click Update Existing to proceed with updating the matched policy with the downloaded file's data.

08
Click "Yes" — Confirm the Policy Update
▼

Click Yes at the confirmation prompt to approve and finalize the policy update with the downloaded transaction.

09
Verify the Lookup Code Is Assigned
▼

Confirm that the Lookup Code has been successfully assigned to the policy. The field should now reflect the carrier's lookup code, indicating the download file is properly linked.

✓ Workflow complete. The download file is now assigned to the correct existing policy and the transaction is removed from Suspense.
Frequently Asked Questions
Why do I need to check "Prospective" and "History" before searching?▼

By default, Epic's Suspense search only surfaces currently active policies. Enabling Prospective includes future-dated policies that haven't yet taken effect, and History includes expired prior-term policies. If the downloaded transaction relates to a renewal or a policy that has already expired, it will not appear without these filters checked — causing you to create a new policy record instead of matching to the correct one.

What does "Select Existing" do versus creating a new policy?▼

Select Existing attaches the downloaded transaction to an account's current policy record rather than generating a brand-new policy. This keeps the account clean and avoids duplicate policies. Always use Select Existing when you can confirm the correct policy is already on the account.

Why sort by the Expiration column?▼

Sorting by Expiration groups policies chronologically, making it much faster to scan for the term that matches the date range on the downloaded file. This is especially useful when an account has multiple years of policy history listed in the results.

What is the Lookup Code and why does it matter?▼

The Lookup Code is the carrier's identifier that links a downloaded transaction to a specific policy in Epic. Once the assignment is complete, this code should appear on the policy record, confirming that future downloads from the carrier will route directly to this policy without landing in Suspense again.

What if I can't find a matching policy even after enabling the filters?▼

If no policy with matching dates appears after enabling Prospective and History, the policy may not yet exist in Epic for this account. In that case, you would need to create the policy manually before returning to Suspense to assign the download. Do not use "Select Existing" if none of the results match the transaction's effective date range.

Does this workflow apply to all download types in Suspense?▼

This workflow covers the standard assignment process for download files where the policy exists on the account but the Lookup Code has not yet been assigned. For more complex scenarios — such as a line type mismatch causing a "Cannot Assign" error — refer to the separate workflow for resolving Line Type Mismatches in Suspense.
