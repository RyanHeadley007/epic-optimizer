Before You Begin

Certificate holder imports require a correctly formatted spreadsheet. Verify that your holder list matches CSR24's expected column structure before starting the import — an incorrectly formatted file will fail silently or load with blank fields. Have the client's policy open in Applied Epic before navigating to CSR24.

Phase 01 Prepare & Access CSR24
1
Prepare the certificate holder spreadsheet
Before logging into CSR24, confirm your holder list is ready. CSR24 expects a specific column layout for import. Typical required fields include:
  • Certificate holder name
  • Address line 1, City, State, ZIP
  • Additional insured designation (if applicable)
  • Holder description or reference number
Tip: Use a prior successful import file as a formatting reference. Column headers must match exactly — CSR24 is case-sensitive on field names.
2
Log into CSR24 and navigate to the client account
Open CSR24 and locate the client whose certificate holders you are importing. Navigate to the Certificates section within the client's account before proceeding to the import tool.
3
Open the Certificate Holders module
Within the client's certificate section, locate and open the Certificate Holders module. This is where the import function is housed — do not attempt to add holders manually one-by-one when you have a list ready for import.
Important: Confirm you are inside the correct client account before initiating an import. Importing holders into the wrong account cannot be easily reversed.
Phase 02 Run the Import
4
Select the Import option and upload your file
Click the Import button within the Certificate Holders module. CSR24 will prompt you to select your spreadsheet file. Browse to your prepared holder list and confirm the upload. Only upload one file per import session.
5
Map the columns to CSR24 fields
CSR24 will display a column-mapping screen. Match each column in your spreadsheet to the corresponding CSR24 field. Review every mapping before confirming — an unmapped required field will cause those rows to import with missing data.
Tip: If you used a correctly formatted template file, CSR24 may auto-map all columns. Still verify each one before proceeding.
6
Review the import preview and confirm
CSR24 will show a preview of the records to be imported. Scan the list for any obvious errors — misspelled names, blank address fields, or duplicate entries. Once satisfied, confirm the import to load all holders into the account.
7
Verify the imported holders
After the import completes, return to the Certificate Holders list and verify the record count matches your source file. Spot-check several holders for address accuracy. If records are missing or malformed, review your source spreadsheet formatting and re-import the affected rows.
Record count mismatch: If the imported count is lower than expected, CSR24 likely skipped rows with missing required fields. Check the import error log if available, correct the source file, and re-run for the failed records only.
Common Questions
What file format does CSR24 accept for certificate holder imports?▼

CSR24 typically accepts .CSV or .XLSX files for certificate holder imports. Confirm with your CSR24 administrator which format is configured for your agency's instance, as this can vary. When in doubt, export your spreadsheet as .CSV to avoid any Excel formatting conflicts.

Can I import holders to update existing records, or only to add new ones?▼

CSR24's import function is generally additive — it adds new holders rather than updating existing ones. If you need to update existing holder information, do so manually on the individual holder record, or remove the outdated records and re-import the corrected list.

What happens if I accidentally import holders into the wrong client account?▼

You will need to manually delete the imported holders from the incorrect account. CSR24 does not have a bulk-undo for imports. To avoid this, always double-check the client account name in your browser tab and the CSR24 breadcrumb before clicking Import.
