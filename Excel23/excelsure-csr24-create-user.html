Before You Start

The CSR24 user is created from an existing Epic contact — start in Applied Epic, not in CSR24. Information from the Epic contact record (name, email, phone) prepopulates into CSR24 when the portal account is created, so confirm the Epic contact details are correct first. At minimum, the contact must have a First Name, Last Name, and Email Address on file.

Contact Navigation ↓ Portal Configuration ↓ Account Finalization ↓
Phase 01 Contact Navigation in Applied Epic
1
Start on the Account Screen
Open the account in Applied Epic for which you are creating portal access. All CSR24 user setup begins from the account record — not from a global menu — because the new user will be tied to this specific account.
2
Click "Contacts"
From the account screen, navigate to the Contacts area. This is where every contact associated with the account is listed, and where portal access is initiated for each one.
3
Locate and open the correct contact
Find the contact you want to create portal access for and double-click to open the contact record.
Example: If you are setting up Joe Cool as a CSR24 user, double-click his contact entry to open his record.
4
Click the "Create Account" link
From the open contact record, click the Create Account link. This launches the CSR24 portal in a new window and begins the user creation process for the selected contact.
What this does: Applied Epic hands off the contact's information to CSR24, which uses it to prepopulate the new user record. You will not need to re-type the name, email, or phone — that data carries over automatically.
Phase 02 Portal User Configuration in CSR24
5
CSR24 opens the portal page for the contact
After clicking Create Account, CSR24 opens the new user setup screen for the selected contact. You are now in CSR24 — no longer in Applied Epic — and the remaining configuration is done from this screen.
6
Verify prepopulated contact information
Contact data from Applied Epic will prepopulate the user information fields in CSR24. Review for accuracy before continuing.
Minimum required fields:
  • First Name
  • Last Name
  • Email Address
If a required field is missing: Cancel out of CSR24, go back to the Epic contact record, fix the missing information, and then re-launch the Create Account workflow from step 4.
7
Select the correct User Group
Check the Clients user group checkbox, then select the appropriate sub-group based on the account type:
  • Personal Lines Portals — select Personal Lines
  • Commercial Lines Portals — select Commercial Lines
Why this matters: The user group determines what the insured sees and is allowed to do in the portal. Selecting the wrong group means the user will land on the wrong type of dashboard, see policies in the wrong format, and may not have access to features they should — or may have access to ones they shouldn't.
8
Enter the Username and click "Change Password"
Enter the username the new user will use to log in. The most common convention is to use the user's email address as the username — but it does not have to be an email; any unique identifier works.
Once the username is entered, click Change Password to set the initial password.
Best practice: Stay consistent across users — pick a convention (email-as-username or first.last) and use it for every new account. Mixed conventions create support headaches later when an insured can't remember which format you used for them.
9
Set a temporary password and submit
Enter the new temporary password and click Submit. This is the password the user will use for their first login.
Leave "Require User to change password on next login" checked. This forces the user to set their own password on first login, so the temporary password is only ever known briefly and only for the handoff.
Tip: Take note of the temporary password — you will need it when sending the login credentials to the client. Once you close this screen without recording it, you cannot retrieve it later; you would have to set a new one.
10
Select the Start Page
From the Start Page dropdown, select the page the user will land on when they first log into the portal. The start page should reflect what the user actually needs to do most often.
Example: For a user whose primary purpose is issuing certificates, assign the Certificates Only Start Page from the dropdown — they will go directly to the certificate workflow on login instead of navigating from a generic dashboard.
11
Select the App Screen
From the App Screen dropdown, select the default app screen layout the user will see:
  • Commercial Lines accounts — select Initial Commercial Default
  • Personal Lines accounts — update to the corresponding Personal option
Match the App Screen to the User Group: If you selected Commercial Lines in step 7, the App Screen should be the Commercial default. Mixing a Personal Lines group with a Commercial App Screen (or vice versa) leads to a portal experience that doesn't match what the user expects to see.
Phase 03 Account Finalization
12
Click "Save"
Click Save to commit the new user account. The portal user is now created and active, and the username and temporary password can be sent to the client so they can complete their first login.
Before you walk away: Confirm the user appears in the CSR24 user list for the account. If the save fails silently (rare, but it happens with a network blip), the user will not be there — and you will need to redo the configuration from step 5.
Next: Send the credentials to the client — username + temporary password + the portal login URL. They will be prompted to change the password on first login.
Common Questions
The contact's email or name didn't prepopulate correctly — what do I do?▾

This almost always means the data is incorrect or missing on the Epic contact record. Cancel out of CSR24, go back to the Epic contact, fix the issue at the source, save the contact record, and then re-launch the Create Account workflow from step 4. Editing the data only inside CSR24 will work for that single user, but the Epic record will still be wrong — and the next process that pulls from it will be wrong as well. Fix it once, at the source, and it stays fixed.

Should the username be the email address or something else?▾

Email-as-username is the most common convention because it's something the user already knows and is unlikely to forget. The downside is that if the user's email changes, you have to update it in two places — the contact record and the username. Either convention works fine; the important thing is to pick one and use it consistently across every CSR24 user you set up. Mixed conventions create avoidable support calls.

What happens if I forget to take note of the temporary password before saving?▾

You cannot retrieve a temporary password once it's set — CSR24 doesn't display it back to you. If you forget to record it, the fix is to go back into the user record and set a new temporary password using the same Change Password workflow. Make sure "Require User to change password on next login" is still checked, then send the new temporary password to the client. It's a small redo, but easy to avoid by copying the password somewhere safe the moment you create it.

Can I change the User Group, Start Page, or App Screen after the user is saved?▾

Yes — all of these can be edited later from the user's record in CSR24. If you assign the wrong group or start page initially, just open the user, change the setting, and save. The user will see the new configuration the next time they log in. That said, it's much cleaner to set them correctly from the start, particularly for the User Group, because changing group assignments can affect what content and policies the user can already see in their portal history.

What if I need to create a user who has access to both Personal and Commercial Lines?▾

This is uncommon for standard insured users — most clients have one or the other. If a contact genuinely needs cross-line access (for example, a business owner who also has personal policies tied to the same agency contact), the User Group section in CSR24 supports multiple group selections. Check both Personal Lines and Commercial Lines boxes under the Clients group. The Start Page and App Screen will still need to be set to one default, so pick the one that reflects what the user does most often — they can navigate to the other from within the portal.

Where is the "Create Account" link on the contact record?▾

The Create Account link is on the contact record itself, visible once the contact is open (after the double-click in step 3). If you don't see it, the most common reasons are: the contact already has a CSR24 account (in which case the link will say something different, like "Edit Account"), the CSR24 integration is not enabled at your user level in Epic, or the contact record is missing required information that prevents account creation. Check those in order and most issues resolve quickly.
