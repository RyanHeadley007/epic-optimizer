Epic Processing Guide
Cannot Assign: Line Type
Mismatch in Suspense

How to resolve a line type mismatch when a downloaded transaction cannot be assigned to a matching policy line in Epic's Interface Suspense.

26 Steps
~4 Minutes
Applied Epic
Scenario
A downloaded transaction arrives in Interface Suspense with a "Cannot Assign" error because the line type in Epic differs from what the carrier sent — for example, the carrier sends a Dwelling Fire transaction but the existing line is set up as a Homeowner's Application. This workflow corrects the mismatch directly from within Suspense without rebuilding the policy from scratch.
Interactive Walkthrough
Live Step-by-Step Guide — Epic Optimizer · 26 Steps
Processing Steps
Phase 1 — Locate & Link the Transaction
01
Starting in Interface Suspense Section of Epic
▼

Begin in the Interface Suspense section of Epic where unprocessed downloaded transactions are held.

02
Select the Transaction Line
▼

Identify and select the downloaded transaction that has the line type mismatch.

03
Click "Find"
▼

Click the Find button to search for a matching policy line on the account.

04
Highlight the Line with Matching Effective & Expiration Dates
▼

Highlight the policy line whose effective and expiration dates match the downloaded transaction.

⚠ Make sure the dates align exactly with the transaction — do not select a line with different dates.
05
Click "Select Existing"
▼

Choose Select Existing to link the downloaded transaction to the existing policy on the account rather than creating a new one.

06
Click "Add Line"
▼

Click Add Line to add the new downloaded line type to the existing policy.

07
Click "Yes" — First Confirmation
▼

Click Yes at the first confirmation prompt to proceed with adding the new line.

08
Click "Yes" — Second Confirmation
▼

Click Yes again at the secondary confirmation prompt.

Phase 2 — Process the Download
09
Click "Actions"
▼

Click the Actions menu to access processing options for the transaction.

10
Click "Policies"
▼

Select Policies from the Actions menu.

11
Click "Finish"
▼

Click Finish to complete the download processing step.

12
Click "OK"
▼

Click OK to acknowledge the confirmation dialog and continue.

Phase 3 — Cancel the Mismatched Line
13
Click "Dfire" — Select the Dwelling Fire Line
▼

Navigate to the policy and select the Dfire (Dwelling Fire) line — the correctly downloaded line that was just added.

14
Select the Mismatched Line to Cancel
▼

Highlight the original mismatched line (e.g. Homeowner's Application) that needs to be removed.

15
Click "Cancel"
▼

Click Cancel to initiate cancellation of the mismatched line.

16
Enter the Cancellation Date
▼

Click the date text field and enter the cancellation effective date.

⚠ Always use the original policy effective date — not today's date — to avoid premium discrepancies.
17
Click the Confirmation Checkbox
▼

Click the checkbox to confirm the cancellation details before proceeding.

18
Click "i" (Issue)
▼

Click the i (Issue) button to initiate the cancellation workflow.

19
Handle the CPOL Activity
▼

An activity selection window will appear. Complete the following in sequence:

  • Select CPOL from the activity list
  • Click the Closed field to mark the activity as closed
  • Click Finish to complete the activity workflow
20
Click "Yes" — Incomplete Tasks Warning
▼

If a prompt appears warning about incomplete tasks, click Yes to proceed.

ℹ This message may or may not appear — click Yes if it does and continue.
Phase 4 — Issue Cancellation & Save
21
Click "Actions" Again
▼

Return to the Actions menu on the mismatched line to finalize the cancellation.

22
Click "Issue Cancellation"
▼

Select Issue Cancellation from the Actions menu to formally issue the cancellation on the mismatched line.

23
Change the Status Description
▼

Update the Status Description field on the cancellation screen before saving.

24
Click "ECU" — Entered in Error
▼

Choose ECU – Entered in Error as the cancellation reason. This accurately reflects that the original line was created with the wrong policy type.

25
Click "Save"
▼

Click Save to finalize the cancellation. The workflow is now complete — the mismatched line has been removed and the correct Dwelling Fire line is active on the policy.

✓ Workflow complete. The downloaded transaction is now properly linked to the correct line type.
Frequently Asked Questions
What causes a "Cannot Assign" error in Suspense?▼

This error occurs when the carrier sends a download transaction for one policy type (e.g. Dwelling Fire) but the corresponding line in Epic was set up under a different type (e.g. Homeowner's Application). Epic cannot auto-match them, so the transaction lands in Suspense for manual resolution.

What does "Select Existing" do vs. creating a new policy?▼

Select Existing attaches the downloaded transaction to the account's current policy rather than generating a brand-new policy record. This keeps the account clean and avoids duplicate policies.

What is the CPOL activity and why must I close it?▼

CPOL is the cancellation policy activity Epic automatically generates when a cancellation is initiated. It must be selected and marked Closed to confirm the workflow step is complete — otherwise the cancellation cannot proceed to issuance.

Why use ECU (Entered in Error) as the cancellation reason?▼

ECU accurately describes what happened — the original line was created under the wrong policy type. Using this reason code keeps the audit trail clean and signals to anyone reviewing the account that the cancellation was a data correction, not a true policy cancellation.

What if the "Incomplete Tasks" warning doesn't appear?▼

That's fine — the warning is conditional and may not always appear. If it doesn't show up, simply continue to Actions → Issue Cancellation.

What date should I use when canceling the mismatched line?▼

Always cancel back to the original policy effective date — not today's date. Using the wrong date will create premium discrepancies and potential accounting issues on the account.
